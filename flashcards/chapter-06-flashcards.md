## Chapter 6: Windows Security Settings: Permissions, UAC, BitLocker/EFS, and Data Destruction — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | List the four standard NTFS permissions tested on 220-1202 (basic level, ascending restriction to least restrictive). | Read → Read & Execute → Write → Modify → Full Control (Full Control is broadest, includes taking ownership and changing permissions). Exam tip: Full Control ⊃ Modify ⊃ Read & Execute. |
| 2 | List the three Share permissions in Windows. | Read, Change, Full Control. Exam tip: Share permissions are simpler/coarser than NTFS permissions and only apply to network access, never local access. |
| 3 | Rule: Accessing a resource over the network where NTFS = Modify and Share = Read. What's the effective permission? | Read — the most restrictive of the combined NTFS and Share permissions always applies for network access. Exam tip: this is one of the most heavily tested rules on the exam. |
| 4 | Copying a file within the SAME NTFS volume — what permissions does it get? | Inherits the permissions of the DESTINATION folder. Exam tip: copy = always inherit destination permissions, regardless of volume. |
| 5 | Moving a file within the SAME NTFS volume — what permissions does it get? | Retains its ORIGINAL permissions (no inheritance change). Exam tip: same-volume move = keep original permissions; this is the one exception to inheriting destination permissions. |
| 6 | Moving a file ACROSS different NTFS volumes — what permissions does it get? | Inherits the destination folder's permissions. Exam tip: a cross-volume move is internally treated as a copy + delete, so it behaves like a copy. |
| 7 | Name the four UAC notification levels in Windows. | 1) Always notify, 2) Notify only when apps try to make changes (default, dims desktop), 3) Notify only when apps try to make changes (no dim), 4) Never notify. Exam tip: default level does NOT prompt for user-initiated system setting changes, only program-initiated ones. |
| 8 | BitLocker vs EFS — when to use which? | BitLocker: whole-drive encryption, protects against offline/physical theft (e.g., stolen laptop), typically requires TPM 1.2+ or a USB startup key. EFS: per-file/folder encryption tied to a user's certificate/key pair, protects data from other local users on a shared multi-user machine. Exam tip: BitLocker = whole disk & device loss scenario; EFS = per-user file privacy on shared systems. |
| 9 | What hardware component does BitLocker typically rely on for key storage, and what's the fallback if it's missing? | TPM (Trusted Platform Module) chip, version 1.2 or higher. If no TPM is present, BitLocker can be configured (via Group Policy) to use a USB flash drive as a startup key instead. A recovery key is also generated for backup access. |
| 10 | Does degaussing work on SSDs? | No. Degaussing disrupts magnetic fields and is only effective on magnetic media (HDDs, tapes). SSDs use flash memory with no magnetic properties, so degaussing does NOT securely erase them. Exam tip: for SSDs use ATA Secure Erase, crypto-erase, or physical destruction. |
| 11 | What is a Certificate of Destruction and when is it needed? | A formal document from a data destruction vendor/process confirming that a specific device was destroyed and data is unrecoverable. Required for compliance/audit trails when disposing of drives containing sensitive or regulated data. |
| 12 | Name the three Windows Defender Firewall network profiles and their default restrictiveness order. | Public (most restrictive) → Private (moderate, trusted home/work network) → Domain (managed by AD/Group Policy). Exam tip: Public profile disables network discovery and blocks most inbound connections by default. |
